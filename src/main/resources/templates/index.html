에이전트 패턴 비교 실습

같은 질문을 세 가지 패턴으로 처리하고, 각 단계를 누가 결정했는지 실행 기록으로 비교합니다.

Step 9 · /api/search/coordinator

Coordinator

코드가 제어

처리 순서가 코드에 고정되어 있습니다. LLM은 정규식이 실패할 때 검색 조건 추출에만 쓰입니다. 빠르고 결과가 항상 같습니다.

Step 10 · /api/search/tool-calling

Tool Calling 에이전트

LLM이 제어

LLM이 어떤 Tool을 어떤 인자로 몇 번 부를지 결정합니다. 유연하지만 모델에 따라 결과가 달라집니다.

Step 11 · /api/search/orchestrator

Orchestrator-Workers

LLM이 나누고 Worker가 실행

LLM이 요청을 여러 작업으로 나누고, Worker가 병렬로 검색한 뒤, LLM이 결과를 비교해 추천합니다.

LLM 패턴
코드 (개발자가 순서 결정) LLM (판단·계획·요약) Tool (LLM이 호출 요청) Worker (Orchestrator가 맡긴 작업)

예시를 고르거나 문장을 입력한 뒤 실행해 보세요.
